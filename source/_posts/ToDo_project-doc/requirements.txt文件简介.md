# requirements.txt 文件简介


`requirements.txt` 是 Python 项目中用于**记录和管理项目依赖包**的标准文件。

简单来说，它就像是一张 **“购物清单”** 或 **“配方表”**，告诉其他人（或者部署服务器）：“要运行这个项目，你需要安装以下这些 Python 库以及它们的具体版本。”

<!--more-->


### 1. 核心作用


*   **环境复现**：确保在任何电脑（你的、同事的、生产服务器）上安装的依赖包版本完全一致，避免“在我电脑上能跑，在你那就不行”的问题。
*   **一键安装**：配合 `pip` 工具，只需一条命令即可安装所有需要的库。
*   **版本锁定**：明确指定每个库的版本号，防止因为某个库自动升级导致代码报错。

---


### 2. 常用知识点与语法


#### A. 基本格式


每一行代表一个依赖包，格式通常为：
```text

包名==版本号

```
例如你项目中的：
```text

fastapi==0.115.0
sqlalchemy==2.0.36

```


#### B. 版本约束符号（非常重要）


在 `requirements.txt` 中，你经常会看到不同的符号，它们代表不同的版本策略：

| 符号 | 含义 | 示例 | 说明 |
| :--- | :--- | :--- | :--- |
| `==` | **精确版本** | `fastapi==0.115.0` | 必须安装这个特定版本。最稳定，推荐生产环境使用。 |
| `>=` | **最低版本** | `python>=3.11` | 安装 3.11 或更高版本。 |
| `<=` | **最高版本** | `numpy<=1.24.0` | 安装 1.24.0 或更低版本。 |
| `>` | **高于** | `pip>20.0` | 必须高于 20.0 版。 |
| `<` | **低于** | `django<4.0` | 必须低于 4.0 版（通常用于避免不兼容的大版本更新）。 |
| `~=` | **兼容版本** | `requests~=2.28.0` | 等价于 `>=2.28.0, ==2.28.*`。允许小版本更新，但锁定大版本。 |
| (无符号) | **最新版本** | `uvicorn` | 不指定版本，默认安装当前最新的稳定版。**不推荐**，容易导致不可控的更新。 |


#### C.  extras (额外依赖)


有些库有可选功能，需要额外安装依赖。用方括号 `[]` 表示。
*   示例：`uvicorn[standard]`
*   解释：安装 `uvicorn` 的同时，也安装其推荐的额外性能优化包（如 `websockets`, `httptools` 等）。


#### D. 注释


以 `#` 开头的行会被忽略，用于备注。
```text

# 这是数据库异步驱动
asyncpg>=0.30.0

```

### 3. 常用命令


#### 1. 生成 requirements.txt


当你开发完项目，想把当前环境的所有包导出来：
```bash

pip freeze > requirements.txt

```
*   **注意**：`pip freeze` 会导出**当前环境中所有**已安装的包（包括那些你间接依赖的包）。这通常是最安全的做法，因为它锁定了整个依赖树。


#### 2. 安装依赖


拿到别人的项目后，一键安装所有依赖：
```bash

pip install -r requirements.txt

```
*   `-r` 表示 "recursion递归"，后面跟文件名。


#### 3. 更新单个包


如果想更新某个包并同步到文件：
```bash

pip install --upgrade fastapi
pip freeze > requirements.txt  # 重新生成文件以记录新版本

```

---

### 4. 最佳实践建议


1.  **不要手动编辑版本号**：除非你很确定，否则建议先用 `pip install` 安装包，再用 `pip freeze > requirements.txt` 生成文件，这样能保证版本号的准确性。
2.  **区分开发依赖和生产依赖**：
    *   大型项目通常会有 `requirements.txt` (生产环境) 和 `requirements-dev.txt` (开发环境，包含测试工具、lint 工具等)。
    *   在你的 ToDo-App 这种小型项目中，放在一起也可以，但要注意不要把仅用于开发的工具（如 `pytest`）混入生产部署列表，除非你不在意镜像体积。
3.  **定期更新**：依赖包会有安全漏洞修复。定期运行 `pip list --outdated` 检查是否有旧版本，并谨慎更新。
4.  **虚拟环境**：务必在 **虚拟环境** (venv) 中生成 `requirements.txt`。如果你在全局环境生成，里面会包含很多与你项目无关的系统级包，导致文件巨大且混乱。


### 总结


在你的 ToDo-App 项目中，`requirements.txt`是后端环境的**基石**。只要有了它和 Python 3.11+，任何人可以在几分钟内搭建起和你一模一样的后端运行环境。
